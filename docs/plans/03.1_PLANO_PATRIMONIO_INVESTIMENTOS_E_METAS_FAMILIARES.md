## 2. MATRIZ DE REFINAMENTO & CORREÇÕES DO MODO FAMILIAR (PARTE I)

| # | Item Diagnosticado | Causa Técnica Raiz | Correção / Refinamento Canônico |
|---|---|---|---|
| **R1** | **Teto de gasto divergente** | `MoneyInput` opera em **centavos** (ex.: `500000`). O formulário gravava `500000` direto no campo `monthly_budget` do Postgres (que armazena Reais, `numeric(12, 2)`). A RPC `get_family_consolidation` multiplicava por 100, inflando o teto para 50 milhões de centavos. Na reabertura para edição, valores eram dessincronizados. | Padronizar a borda: dividir por 100 ao enviar ao banco (`monthly_budget = cents / 100`). Multiplicar por 100 ao carregar para edição e exibição (`cents = Math.round(monthly_budget * 100)`). Alinhamento 100% com `HouseholdCeilingCard`. |
| **R2** | **Exclusão de família inexistente** | Havia apenas botão "Sair da Família", que chamava `leave_family` sem a flag `p_disband = true`. Para o proprietário (`owner`) com outros membros ou convites, a RPC no banco bloqueava por segurança (`'Como proprietário, você deve transferir a titularidade ou confirmar a dissolução da família.'`). | Criar fluxo explícito de **"Excluir Família"** para o titular (com modal destrutivo de dupla confirmação) disparando `leaveFamily({ disband: true })`. Membros comuns mantêm o botão "Sair da Família". |
| **R3** | **Página vazia sem família criada** | Quando o Modo Familiar estava habilitado nas configurações mas nenhuma família havia sido criada, `useFamilyConsolidation` retornava nulo e o componente caía em `{consolidation ? (...) : null}`, deixando a tela em branco. | Implementar `EmptyState` canônico (ícone `Users`, título informativo, explicação de privacidade) com **botão CTA de criação direta na própria página `/familia`**, sem obrigar navegação até Configurações. |
| **R4** | **Navegação com Modo Familiar desativado** | `sidebar.tsx`, `bottom-nav.tsx` e `more-menu-sheet.tsx` avaliavam `Boolean(myFamilyData?.family || isFamilyModeEnabled)`. Se o usuário desativasse o switch, o fato de ter tido família mantinha a rota visível. | Condicionar a visibilidade de `/familia` estritamente a `isFamilyModeEnabled`. Se desativado, a rota desaparece de toda a navegação (Sidebar, BottomNav e Menu Mais). Acesso direto à URL redireciona para `/`. |
| **R5** | **Erro ao gerar link de convite** | A RPC `invite_family_member` foi criada com `set search_path = public, pg_temp;` e chamava `gen_random_bytes(24)`. Como no Supabase a extensão `pgcrypto` reside no schema `extensions`, a execução falhava com `function gen_random_bytes(integer) does not exist`. | 1) O frontend gera token seguro via Web Crypto API (`crypto.randomUUID().replace(/-/g, '')`) e envia no payload; 2) Migration atualizando a RPC para `set search_path = public, extensions, pg_temp;` com fallback seguro usando `gen_random_uuid()`. |
| **R6** | **Participante Único & Troca de Família** | Usuário que já pertencia a outra família e abria um convite recebia apenas um aviso estático bloqueante, exigindo ir manualmente em configurações para sair. | Na página do convite: se já pertencer à família do convite, exibe aviso e botão para ir a `/familia`; se pertencer a **outra família**, exibe card explicativo com ação assistida: *"Sair de [Família Atual] e Entrar em [Nova Família]"*, com confirmação segura e zero perda de transações. |
| **R7** | **Zero Data Bleed na Dissolução/Saída** | Receio de perda de lançamentos ao sair ou excluir a família. | Reforçar na interface e documentar: sair ou dissolver apenas desvincula o `family_id` e a flag `is_family` das despesas e receitas. **Nenhuma transação pessoal, conta ou saldo bancário é excluído.** |
| **R8** | **Múltiplos Membros & Limite Canônico (Máx. 6)** | Textos limitados a casais e ausência de barreira de escala. Grupos sem limite podem desestruturar o algoritmo de transferências mínimas Pix e poluir visualmente a barra de equilíbrio no mobile. | **Teto de 6 Participantes:** 1 Titular (Owner) + até 5 Membros. Acomoda cônjuge, filhos e dependentes com legibilidade máxima. Validação no banco (`invite_family_member`) e na UI com contador `X de 6 membros` e desativação do botão ao atingir o teto. Filtros no extrato adaptados para até 6 membros. |
| **R9** | **Padronização do Seletor de Data** | O `MonthPicker` em `/familia` estava espremido no cabeçalho ao lado do ícone de ajustes (`w-64`), desalinhado do design system das telas principais (`/`, `/transacoes`, `/orcamentos`). | Reposicionar o `<MonthPicker />` como barra horizontal full-width padronizada logo abaixo do cabeçalho da página. O cabeçalho passa a conter título, badge da família e botões de ação rápida. |
| **R10** | **Ações Rápidas na Página `/familia`** | Gestões básicas (convidar membro, alterar teto, dissolver) exigiam navegar até `/configuracoes?tab=familia`. | Incluir atalhos diretos no cabeçalho de `/familia`: botão *"Convidar Membro"* e menu de configurações rápidas da família. |

## 3. ESPECIFICAÇÃO DE DADOS & SCHEMAS (PARTE I + PARTE II)

### 3.1 Migration de Correção da RPC de Convites, Limite de 6 Membros & Integridade de Teto
```sql
-- migration: 20260101000081_fix_family_invite_token_and_budget.sql

-- 1. Atualizar RPC invite_family_member com limite de 6 membros, extensions no search_path e fallback seguro
CREATE OR REPLACE FUNCTION public.invite_family_member(
  p_family_id uuid default null,
  p_invited_email text default null,
  p_role text default 'member',
  p_token text default null
)
RETURNS jsonb
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, extensions, pg_temp
AS $$
DECLARE
  v_user_id uuid := auth.uid();
  v_family_id uuid;
  v_email text;
  v_role text := coalesce(p_role, 'member');
  v_token text;
  v_invite record;
  v_active_members_count int;
  v_pending_invites_count int;
BEGIN
  -- 1. Autenticação fail-closed
  IF v_user_id IS NULL THEN
    RAISE EXCEPTION 'Não autenticado.' USING errcode = '28000';
  END IF;

  IF NOT public.is_current_user_active() THEN
    RAISE EXCEPTION 'Usuário inativo ou não autorizado.' USING errcode = '42501';
  END IF;

  -- 2. Resolver family_id
  IF p_family_id IS NOT NULL THEN
    v_family_id := p_family_id;
  ELSE
    SELECT fm.family_id INTO v_family_id
    FROM public.family_members fm
    WHERE fm.user_id = v_user_id
    LIMIT 1;
  END IF;

  IF v_family_id IS NULL THEN
    RAISE EXCEPTION 'Família não encontrada.' USING errcode = 'P0002';
  END IF;

  -- 3. Autorização: apenas owner ou admin podem convidar
  IF NOT public.is_family_admin(v_family_id, v_user_id) THEN
    RAISE EXCEPTION 'Apenas administradores podem convidar membros para a família.' USING errcode = '42501';
  END IF;

  -- 4. Invariante: Teto de 6 participantes na família
  SELECT count(*) INTO v_active_members_count
  FROM public.family_members
  WHERE family_id = v_family_id;

  SELECT count(*) INTO v_pending_invites_count
  FROM public.family_invites
  WHERE family_id = v_family_id AND status = 'pending' AND expires_at > now();

  IF (v_active_members_count + v_pending_invites_count) >= 6 THEN
    RAISE EXCEPTION 'A família já atingiu o limite máximo de 6 participantes (membros ativos e convites pendentes).' USING errcode = '22023';
  END IF;

  -- 5. Validação de papel
  IF v_role NOT IN ('member', 'admin') THEN
    RAISE EXCEPTION 'Papel de convite inválido (permitido apenas member ou admin).' USING errcode = '22023';
  END IF;

  -- 6. Validação de e-mail se fornecido
  IF p_invited_email IS NOT NULL AND trim(p_invited_email) != '' THEN
    v_email := lower(trim(p_invited_email));
    IF length(v_email) NOT BETWEEN 3 AND 255 OR v_email !~ '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' THEN
      RAISE EXCEPTION 'Formato de e-mail inválido.' USING errcode = '22023';
    END IF;

    IF EXISTS (
      SELECT 1 FROM public.family_members fm
      JOIN public.profiles p ON p.id = fm.user_id
      WHERE fm.family_id = v_family_id AND lower(p.email) = v_email
    ) THEN
      RAISE EXCEPTION 'Este usuário já é membro da família.' USING errcode = '23505';
    END IF;

    UPDATE public.family_invites
    SET status = 'revoked'
    WHERE family_id = v_family_id AND lower(invited_email) = v_email AND status = 'pending';
  ELSE
    v_email := NULL;
  END IF;

  -- 7. Geração de token à prova de falha
  IF p_token IS NOT NULL AND trim(p_token) != '' THEN
    v_token := trim(p_token);
    IF length(v_token) NOT BETWEEN 6 AND 64 OR v_token !~ '^[a-zA-Z0-9_-]+$' THEN
      RAISE EXCEPTION 'Formato de token de convite inválido.' USING errcode = '22023';
    END IF;
  ELSE
    BEGIN
      v_token := encode(gen_random_bytes(24), 'hex');
    EXCEPTION WHEN OTHERS THEN
      v_token := replace(gen_random_uuid()::text, '-', '') || replace(gen_random_uuid()::text, '-', '');
      v_token := substr(v_token, 1, 48);
    END;
  END IF;

  -- 8. Inserção do convite
  INSERT INTO public.family_invites (
    family_id, invited_by, invited_email, token, role, status, expires_at
  ) VALUES (
    v_family_id, v_user_id, v_email, v_token, v_role, 'pending', now() + interval '7 days'
  ) RETURNING * INTO v_invite;

  RETURN jsonb_build_object(
    'id', v_invite.id,
    'family_id', v_invite.family_id,
    'token', v_invite.token,
    'role', v_invite.role,
    'invited_email', v_invite.invited_email,
    'status', v_invite.status,
    'expires_at', v_invite.expires_at,
    'created_at', v_invite.created_at
  );
END;
$$;
```

-- 1. Colunas de compartilhamento na tabela de investimentos
ALTER TABLE public.portfolio_assets 
  ADD COLUMN IF NOT EXISTS is_family BOOLEAN NOT NULL DEFAULT FALSE,
  ADD COLUMN IF NOT EXISTS family_id UUID REFERENCES public.families(id) ON DELETE SET NULL,

-- 2. Tabela de Metas Patrimoniais da Família
CREATE TABLE IF NOT EXISTS public.family_wealth_goals (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  family_id UUID NOT NULL REFERENCES public.families(id) ON DELETE CASCADE,
  title TEXT NOT NULL CHECK (length(trim(title)) BETWEEN 2 AND 120),
  target_cents BIGINT NOT NULL CHECK (target_cents > 0),
  target_date DATE,
  goal_type TEXT NOT NULL CHECK (
    goal_type IN ('emergency_reserve', 'wealth_accumulation', 'passive_income', 'acquisition')
  ),
  monthly_passive_income_target_cents BIGINT DEFAULT NULL,
  linked_asset_classes TEXT[] DEFAULT NULL,
  notes TEXT,
  created_by UUID NOT NULL REFERENCES auth.users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_family_wealth_goals_family 
  ON public.family_wealth_goals(family_id);

ALTER TABLE public.family_wealth_goals ENABLE ROW LEVEL SECURITY;

CREATE POLICY "family_wealth_goals_select" ON public.family_wealth_goals
  FOR SELECT TO authenticated
  USING (
    public.is_family_member(family_id, (SELECT auth.uid()))
  );

CREATE POLICY "family_wealth_goals_insert" ON public.family_wealth_goals
  FOR INSERT TO authenticated
  WITH CHECK (
    public.is_family_member(family_id, (SELECT auth.uid()))
  );

CREATE POLICY "family_wealth_goals_update" ON public.family_wealth_goals
  FOR UPDATE TO authenticated
  USING (
    public.is_family_member(family_id, (SELECT auth.uid()))
  );

CREATE POLICY "family_wealth_goals_delete" ON public.family_wealth_goals
  FOR DELETE TO authenticated
  USING (
    public.is_family_admin(family_id, (SELECT auth.uid()))
    OR created_by = (SELECT auth.uid())
  );

## 4. SALVAGUARDAS ARQUITETURAIS & BLINDAGEM DE RLS (D4)

| # | Fragilidade Diagnosticada | Impacto | Salvaguarda Blindada de Engenharia |
|---|---|---|---|
| **S1** | **Vazamento de Carteira Pessoal (Data Bleed)** | Familiar ver ativos privados na listagem comum. | O RLS padrão de `portfolio_assets` continua estritamente `auth.uid() = user_id`. A consolidação familiar ocorre **exclusivamente via RPC `get_family_portfolio_consolidation`** com filtro `is_family = true AND family_id = user_family_id`. |
| **S2** | **Exposição de Dados de Corretora / Notas Fiscais** | Familiar ver número de conta em corretora ou notas privadas do outro. | A RPC sanitiza a saída: omite `broker`, `account_id` e metadados fiscais privados, retornando apenas: Ticker, Classe, Quantidade compartilhada, Cotação média e Valor consolidado. |
| **S3** | **Mutação Cruzada Indesejada** | Familiar tentar editar ou vender ativo do outro. | **Imutabilidade Cruzada:** O RLS de update/delete em `portfolio_assets` bloqueia mutações de terceiros (`user_id = auth.uid()`). Apenas o titular opera seu ativo. |
| **S4** | **Desvinculação Segura (Zero Data Bleed)** | Membro sai ou a família é excluída. | A RPC `leave_family` atualiza `portfolio_assets SET is_family = false, family_id = null WHERE user_id = v_user_id` e `expenses SET is_family = false, family_id = null`. Zero retenção após dissolução. |
