### Oportunidade Única de Mercado (O "Moat" Insuperável)
Nenhum concorrente brasileiro (Mobills, Organizze, Kinvo, Gorila, Status Invest) possui carteira compartilhada seletiva. Ao permitir que casais construam a **Reserva da Casa** e atinjam **Metas Coletivas** mantendo seus ativos individuais 100% privados, o Áxis cria uma retenção de longo prazo quase impossível de ser desfeita (churn zero).

## 3. SALVAGUARDAS ARQUITETURAIS & BLINDAGEM DE RLS (D4)

| # | Risco / Vulnerabilidade | Impacto | Salvaguarda Blindada de Engenharia |
|---|---|---|---|
| **S1** | **Vazamento de Carteira Pessoal (Data Bleed)** | Parceiro ver ações ou criptos privadas na listagem comum. | O RLS padrão de `portfolio_assets` continua estritamente `auth.uid() = user_id`. A consolidação familiar ocorre **exclusivamente via RPC `get_family_portfolio_consolidation`** com filtro `is_family = true AND family_id = user_family_id`. |
| **S2** | **Exposição de Dados da Corretora / Notas** | Parceiro ver número de conta em corretora ou notas fiscais do outro. | A RPC sanitiza a saída: omite `broker`, `account_id` e metadados fiscais privados, retornando apenas: Ticker, Classe, Quantidade compartilhada, Cotação média e Valor atualizado. |
| **S3** | **Mutação Cruzada Indesejada** | Parceiro tentar vender ou editar o ativo do outro. | **Imutabilidade Cruzada:** O RLS de update/delete em `portfolio_assets` e `portfolio_transactions` bloqueia mutações de terceiros (`user_id = auth.uid()`). Somente o titular pode operar seu ativo. |
| **S4** | **Desvinculação Segura (Saída da Família)** | Membro sai da família e ativos continuam visíveis. | O RPC `leave_family` (definido no Plano 03) é estendido para executar: `UPDATE portfolio_assets SET is_family = false, family_id = null WHERE user_id = p_user_id`. Zero retenção de dados após dissolução. |

## 4. CATÁLOGO DE RPCS ATÔMICOS

### 4.1 RPC: `get_family_portfolio_consolidation`
Agrega todos os ativos compartilhados pelos membros da família, calculando posição a valor de mercado e dividendos dos últimos 12 meses.

```sql
CREATE OR REPLACE FUNCTION get_family_portfolio_consolidation(p_family_id UUID)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_user_id UUID := auth.uid();
  v_is_member BOOLEAN;
  v_result JSONB;
BEGIN
  -- 1. Validar se o solicitante é membro da família
  SELECT EXISTS(
    SELECT 1 FROM family_members 
    WHERE family_id = p_family_id AND user_id = v_user_id
  ) INTO v_is_member;

  IF NOT v_is_member THEN
    RAISE EXCEPTION 'Acesso negado: você não pertence a esta unidade familiar.';
  END IF;

  -- 2. Consolidar ativos compartilhados com sanitização
  WITH member_assets AS (
    SELECT 
      pa.id AS asset_id,
      pa.user_id,
      p.display_name AS owner_name,
      pa.ticker,
      pa.name AS asset_name,
      pa.asset_class,
      pa.currency,
      pa.quantity * (pa.family_share_percentage::numeric / 100.0) AS effective_quantity,
      pa.average_price_cents,
      pa.current_price_cents,
      (pa.quantity * (pa.family_share_percentage::numeric / 100.0) * pa.current_price_cents)::bigint AS current_total_value_cents,
      (pa.quantity * (pa.family_share_percentage::numeric / 100.0) * pa.average_price_cents)::bigint AS invested_total_cents
    FROM portfolio_assets pa
    JOIN profiles p ON p.id = pa.user_id
    WHERE pa.family_id = p_family_id 
      AND pa.is_family = TRUE
  ),
  dividends_12m AS (
    SELECT 
      pd.asset_id,
      SUM(pd.net_amount_cents)::bigint AS total_dividends_cents
    FROM portfolio_dividends pd
    JOIN member_assets ma ON ma.asset_id = pd.asset_id
    WHERE pd.payment_date >= (CURRENT_DATE - INTERVAL '12 months')
    GROUP BY pd.asset_id
  )
  SELECT jsonb_build_object(
    'family_id', p_family_id,
    'total_wealth_cents', COALESCE(SUM(ma.current_total_value_cents), 0),
    'total_invested_cents', COALESCE(SUM(ma.invested_total_cents), 0),
    'total_dividends_12m_cents', COALESCE(SUM(d.total_dividends_cents), 0),
    'assets', COALESCE(jsonb_agg(
      jsonb_build_object(
        'asset_id', ma.asset_id,
        'owner_id', ma.user_id,
        'owner_name', ma.owner_name,
        'ticker', ma.ticker,
        'name', ma.asset_name,
        'asset_class', ma.asset_class,
        'quantity', ma.effective_quantity,
        'current_price_cents', ma.current_price_cents,
        'total_value_cents', ma.current_total_value_cents,
        'total_invested_cents', ma.invested_total_cents,
        'dividends_12m_cents', COALESCE(d.total_dividends_cents, 0)
      )
    ), '[]'::jsonb),
    'breakdown_by_member', COALESCE((
      SELECT jsonb_agg(
        jsonb_build_object(
          'user_id', sub.user_id,
          'name', sub.owner_name,
          'total_cents', sub.member_total
        )
      )
      FROM (
        SELECT user_id, owner_name, SUM(current_total_value_cents)::bigint AS member_total
        FROM member_assets
        GROUP BY user_id, owner_name
      ) sub
    ), '[]'::jsonb)
  ) INTO v_result
  FROM member_assets ma
  LEFT JOIN dividends_12m d ON d.asset_id = ma.asset_id;

  RETURN v_result;
END;
$$;
```

### 4.2 RPC: `set_asset_family_sharing`
Alterna com validação e log de auditoria o compartilhamento de um ativo específico.

```sql
CREATE OR REPLACE FUNCTION set_asset_family_sharing(
  p_asset_id UUID,
  p_is_family BOOLEAN,
  p_family_id UUID DEFAULT NULL,
  p_share_percentage INTEGER DEFAULT 100
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
DECLARE
  v_user_id UUID := auth.uid();
  v_asset_owner UUID;
BEGIN
  -- Validar propriedade
  SELECT user_id INTO v_asset_owner FROM portfolio_assets WHERE id = p_asset_id;
  
  IF v_asset_owner IS NULL OR v_asset_owner <> v_user_id THEN
    RAISE EXCEPTION 'Acesso negado: você só pode compartilhar seus próprios ativos.';
  END IF;

  -- Atualizar ativo
  UPDATE portfolio_assets
  SET 
    is_family = p_is_family,
    family_id = CASE WHEN p_is_family THEN p_family_id ELSE NULL END,
    family_share_percentage = CASE WHEN p_is_family THEN p_share_percentage ELSE 100 END,
    updated_at = NOW()
  WHERE id = p_asset_id;

  -- Registrar na auditoria
  INSERT INTO audit_events (user_id, entity_type, entity_id, action, payload)
  VALUES (
    v_user_id,
    'portfolio_asset',
    p_asset_id,
    CASE WHEN p_is_family THEN 'share_family_asset' ELSE 'unshare_family_asset' END,
    jsonb_build_object('family_id', p_family_id, 'percentage', p_share_percentage)
  );

  RETURN jsonb_build_object('ok', true, 'asset_id', p_asset_id, 'is_family', p_is_family);
END;
$$;
```

## 5. CAMADA DE DOMÍNIO PURO (`src/domain/family/wealth.ts`)

Funções 100% puras (sem UI e sem Supabase), testadas com Vitest em centavos:

1. **`calculateFamilyEmergencyReserveHealth(totalFamilyCashCents: number, monthlyFamilyExpensesCents: number): EmergencyReserveReport`**
   - Calcula a autonomia da família em meses de reserva de emergência (`totalFamilyCash / monthlyFamilyExpenses`).
   - Retorna o status: `Crítico (< 3 meses)`, `Moderado (3 a 6 meses)`, `Sólido (6 a 12 meses)` ou `Excelente (> 12 meses)`.
2. **`calculateFamilyPassiveIncomeRunrate(dividends12mCents: number, monthlyFixedExpensesCents: number): PassiveIncomeReport`**
   - Mede o percentual das contas fixas da casa que já são pagas exclusivamente pelos dividendos dos investimentos compartilhados da família.
3. **`calculateFamilyWealthContribution(members: Array<{ userId: string; totalCents: number }>): Array<{ userId: string; percentage: number }>`**
   - Decomposição percentual equilibrada da contribuição patrimonial entre o casal.
